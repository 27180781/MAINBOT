# MAINBOT – עוזר קולי בעברית על Claude למרכזיית טכנוליין

עוזר טלפוני לבעל עסק: מתקשרים למספר, מדברים בעברית חופשית, ו-Claude עונה בקול – אחרי שהוא ניגש בעצמו למערכות העסק דרך שרתי MCP מרוחקים (ה-CRM, ימות המשיח, Lovable, GitHub, מערכת המשחקים). אפשר לשאול "מה קורה בתיבת הפניות?", לבקש "תבדוק אם השבעה באוקטובר פנוי" או להגיד "תשלח לו וואטסאפ עם המחיר" – והבוט מבצע, אחרי שהקריא מה בדיוק הוא עומד לעשות וקיבל "כן".

הבוט נבנה מול ה-**API Module** של מרכזיית טכנוליין: המרכזייה היא לקוח HTTP שפונה לכתובת שלנו, ואנחנו מחזירים לה מודולים בפורמט JSON (הקראה, זיהוי דיבור, ניתוק). הפרוטוקול המלא מתועד ב-[docs/technoline-api-module.md](docs/technoline-api-module.md).

## איך שיחה זורמת

</div>

```text
 [מתקשר] ──קול──▶ [מרכזיית טכנוליין] ──GET──▶ https://<host>/pbx/technoline/<WEBHOOK_SECRET>?PBXphone=...&PBXcallId=...
                                          ◀─JSON─  [simpleMessage "שלום..."] + [stt name=utt_1 max=10]
                        (המרכזייה מקליטה עד 10 שניות ומתמללת)
                                          ──GET──▶ ...?PBXcallId=...&utt_1=מה+קורה+בתיבה
                                                    │  Claude ⇄ כלי MCP (CRM, ימות, ...) – יכול לקחת 5-90 שניות
                                          ◀─JSON─  [simpleMessage "רק רגע, אני בודק."]        ← אחרי PBX_LONG_POLL_MS
                                          ──GET──▶ ...?PBXcallId=...&utt_1=...  (אותם פרמטרים, השרת ממשיך לחכות)
                                          ◀─JSON─  [simpleMessage "יש שתי פניות..."] + [stt name=utt_2]
                                          ──GET──▶ ...&utt_1=...&utt_2=כן
                                          ◀─JSON─  [simpleMessage "להתראות."] + [hangup]
                                          ──GET──▶ ...&PBXcallStatus=HANGUP
                                          ◀─────   {}  (200 ריק)
```

<div dir="rtl">

1. **המרכזייה פונה אלינו.** בכל סבב היא שולחת `GET` לכתובת ה-Webhook עם הפרמטרים הקבועים (`PBXphone`, `PBXcallId`, `PBXcallStatus` ועוד) ומצפה לתשובת JSON תוך כ-30 שניות. בסבב הראשון אנחנו מחזירים את ברכת הפתיחה ומודול `stt`.
2. **זיהוי דיבור מוגבל ל-10 שניות להיגד.** המרכזייה מקליטה, מתמללת ומחזירה את הטקסט כפרמטר. כל היגד מקבל שם ייחודי (`utt_1`, `utt_2`, ...) כי המרכזייה **צוברת** את כל תוצאות המודולים ב-query string ושולחת אותן מחדש בכל בקשה; השם הרץ מאפשר לנו לדעת מה חדש ומה כבר טופל.
3. **Claude עובד ברקע.** הטקסט נכנס ללולאת הכלים של Claude (חיפוש כלים, קריאות MCP, אישורים). זה יכול לקחת יותר מ-30 השניות שהמרכזייה מוכנה לחכות.
4. **מילוי זמן ("רק רגע").** אם התשובה לא מוכנה תוך `PBX_LONG_POLL_MS` (ברירת מחדל 20 שניות, מתחת למגבלת המרכזייה), אנחנו מחזירים משפט קצר להקראה. המרכזייה מקריאה אותו ומיד פונה אלינו שוב עם אותם פרמטרים – והשרת ממשיך להמתין לאותה משימה. אפשר לבחור ב-`/admin` השמעת שקט במקום משפט.
5. **התשובה מוקראת** (Google TTS, חינם) יחד עם מודול `stt` חדש להיגד הבא. כשהמתקשר נפרד, Claude קורא לכלי המקומי `end_call` והשרת מצרף `hangup`.
6. **ניתוק.** המרכזייה שולחת בקשה אחרונה עם `PBXcallStatus=HANGUP`; אנחנו עונים `{}` ריק, רושמים את השיחה ביומן השימוש וסוגרים את הסשן.

## דרישות

- Node.js 22 ומעלה (‏`package.json` דורש 20+, ה-Dockerfile משתמש ב-22).
- מפתח API של Anthropic (`ANTHROPIC_API_KEY`).
- כתובת HTTPS ציבורית (דומיין + תעודה, למשל דרך Caddy או CapRover). נדרשת גם למרכזייה וגם להתחברויות OAuth של שרתי ה-MCP.
- שלוחת API במרכזיית טכנוליין (ראו [הגדרת המרכזייה](#הגדרת-מרכזיית-טכנוליין)).
- שרתי MCP מרוחקים שיש לכם גישה אליהם (אותם מחברים שמופיעים ב-claude.ai).

## חיבור שרתי ה-MCP

הבוט מתחבר לאותם מחברים שאתם משתמשים בהם ב-claude.ai, ישירות מהשרת. הרשימה נמצאת ב-`config/mcp-servers.json`:

</div>

```json
{
  "servers": [
    {
      "name": "crm",
      "label": "CRM חוויה בקליק",
      "description": "לידים, לקוחות, תיבת פניות, יומן, תשלומים",
      "url": "https://<project>.supabase.co/functions/v1/mcp",
      "transport": "auto",
      "enabled": true,
      "auth": { "type": "oauth" },
      "alwaysLoad": ["search_contacts", "get_contact", "list_unanswered"],
      "readOnly": false,
      "excludeTools": ["delete_contact"]
    },
    {
      "name": "github",
      "label": "GitHub",
      "url": "https://api.githubcopilot.com/mcp/",
      "auth": { "type": "bearer", "tokenEnv": "GITHUB_TOKEN" },
      "enabled": false
    }
  ]
}
```

<div dir="rtl">

| שדה | הסבר |
|---|---|
| `name` | מזהה קצר: אותיות קטנות, ספרות, `_` או `-`, עד 20 תווים. משמש כקידומת לשמות הכלים (`crm__search_contacts`) ולשם קובץ הטוקנים. |
| `label` | שם תצוגה (בעברית) בממשק הניהול ובפרומפט. |
| `description` | תיאור קצר (אופציונלי). |
| `url` | כתובת שרת ה-MCP המרוחק. |
| `transport` | `auto` (מנסה Streamable HTTP ואז SSE), `http` או `sse`. |
| `enabled` | `false` מדלג על השרת בלי למחוק אותו. |
| `auth` | `{"type":"oauth"}` – התחברות מהדפדפן; `{"type":"bearer","tokenEnv":"VAR"}` או `{"type":"bearer","token":"${VAR}"}` – טוקן קבוע; `{"type":"headers","headers":{...}}` – כותרות מותאמות; `{"type":"none"}`. |
| `headers` | כותרות נוספות לכל בקשה (הערכים יכולים להפנות ל-`${ENV_VAR}`). |
| `alwaysLoad` | כלים שנטענים לתוך ההקשר של Claude בכל בקשה, בלי חיפוש. 3–6 לשרת מספיקים; השאר נמצאים בחיפוש כלים. |
| `readOnly` | `true` = שום כלי כתיבה מהשרת הזה לא יבוצע מהטלפון. |
| `excludeTools` | כלים שמוסתרים מ-Claude לגמרי. |

### איפה מוצאים את כתובות המחברים

ב-claude.ai: **Settings → Connectors**. למחבר מותאם (Custom connector) הכתובת היא זו שהזנתם כשהוספתם אותו (לחצו על המחבר / "Edit" כדי לראותה). למחברים מהספרייה הכתובת מפורסמת אצל הספק – למשל Lovable: `https://mcp.lovable.dev/mcp`, GitHub: `https://api.githubcopilot.com/mcp/`. ה-CRM ומערכת המשחקים של חוויה בקליק רצים על Supabase Edge Functions (`https://<project>.supabase.co/functions/v1/mcp`).

### התחברות (OAuth)

1. הפעילו את השרת, גלשו ל-`https://<host>/admin`, לשונית **חיבורים**.
2. ליד שרת במצב "נדרשת התחברות" לחצו **התחבר**. הדפדפן עובר לשרת ההרשאות, ובסיום חוזר ל-`<PUBLIC_BASE_URL>/oauth/callback/<name>`.
3. אחרי ההצלחה מספר הכלים של השרת מופיע בטבלה, והפרומפט מתעדכן אוטומטית.

הטוקנים נשמרים ב-`MCP_AUTH_DIR` (‏`.mcp-auth/<name>.json`, הרשאות 0600) ומתרעננים לבד. **התנתק** מוחק אותם.

מהטרמינל אפשר להריץ את אותו תהליך עם הסקריפט `mcp:login` (‏`npm run mcp:login -- crm`), שמשתמש ב-callback מקומי על `MCP_OAUTH_CALLBACK_PORT`. שימו לב: לקוח OAuth שנרשם ל-redirect אחד (טרמינל) נרשם מחדש אוטומטית כשמתחברים מה-redirect השני (‏`/admin`), ולהפך.

### טוקנים קבועים (bearer)

לשרתים כמו GitHub, שמים את הטוקן במשתנה סביבה (למשל `GITHUB_TOKEN`) ומפנים אליו מהקובץ עם `"tokenEnv"`. אין צורך בהתחברות מהדפדפן.

### רשימת הכלים

`npm run mcp:tools` מתחבר לשרתים המוגדרים ומדפיס את הכלים שלהם עם השם המלא (‏`server__tool`) – נוח כדי לבחור מה לשים ב-`alwaysLoad`, ב-`excludeTools` וברשימת הכלים החסומים. את אותה רשימה רואים גם בלשונית **חיבורים** ב-`/admin`.

## הגדרת מרכזיית טכנוליין

1. בממשק הניהול של המרכזייה צרו **שלוחת API** חדשה.
2. כתובת ה-URL: `https://<host>/pbx/technoline/<WEBHOOK_SECRET>` (הכתובת המדויקת מופיעה בלשונית **חיבורים** ב-`/admin` עם כפתור **העתק**). שיטה: **GET**.
3. נתבו אליה מספר (DID) או מקש בתפריט הראשי. כל הפעולות בשיחה (הקראה, זיהוי דיבור, ניתוק) נעשות מתוך השלוחה הזו – אין צורך בשלוחות נוספות.

## ממשק הניהול (`/admin`)

כניסה עם `ADMIN_USER` / `ADMIN_PASSWORD` (‏Basic Auth). הלשוניות:

- **הגדרות** – מודל ורמת מאמץ, מקסימום טוקנים, מספר סבבי מודל לתור, מודל חלופי בסירוב, חיפוש כלים (regex/bm25); קול להקראה, מה להשמיע בזמן ההמתנה (משפט או שקט), ברכות פתיחה וסיום, משך הקלטה, מגבלת תורות ותורות שקטים; מספרים מורשים, קוד גישה, אישור לפעולות כתיבה, כלים חסומים; הנחיות נוספות לפרומפט. כל שינוי נשמר ב-`data/settings.json` ונכנס לתוקף מיד, בלי הפעלה מחדש.
- **חיבורים** – כתובת ה-Webhook למרכזייה, שיחות פעילות כרגע, וטבלת שרתי ה-MCP עם מצב החיבור, מספר הכלים וכפתורי התחבר / התנתק / חבר מחדש.
- **שימוש וטוקנים** – היום / 7 ימים / 30 ימים / הכול: שיחות, תורות, בקשות ל-Claude, קריאות כלים, טוקנים (כולל קריאה וכתיבה למטמון) ואומדן עלות בדולרים; פירוט לפי מודל, יום וכלי; רשימת שיחות – לחיצה פותחת את התמליל המלא כולל הכלים שנקראו.
- **בדיקה** – צ'אט בטקסט עם אותו סוכן ואותם כלים, כדי לבדוק חיבורים והנחיות בלי להתקשר.
- **כללים והוראות** – הכללים הקבועים שבעל העסק הכתיב בטלפון ("מעכשיו תמיד...") ועורך לקובץ `config/instructions.md`.
- **משימות יזומות** – בדיקות שהעוזר מריץ בעצמו לפי לוח זמנים או אירוע ושולח עליהן הודעה (ראו למטה).
- **פרומפט** – פרומפט המערכת המלא כפי שהוא נשלח ל-Claude.

בנוסף: `/health` מחזיר JSON עם מצב כל שרת MCP, מספר השיחות הפעילות והמודל – ללא סיסמה, נוח לניטור.

## אותו עוזר בתוך ה-CRM (Chat API)

המנוע זמין גם כצ'אט טקסט למערכות אחרות, למשל במקום העוזר המובנה ב-CRM: `POST /api/v1/chat` עם `Authorization: Bearer <CHAT_API_KEY>` וגוף `{ "message": "...", "sessionId": "...", "userName": "..." }` מחזיר `{ "text": "...", "toolCalls": [...] }`. אותם כלים, אותם כללים קבועים ואותו אישור לפני פעולות; הפרומפט מותאם לצ'אט (עיצוב קל מותר). מדריך מלא עם דוגמת Edge Function ל-Supabase: [docs/CRM-INTEGRATION.md](docs/CRM-INTEGRATION.md).

## משימות יזומות – העוזר פונה אליכם

העוזר יכול גם ליזום: "כל בוקר בשמונה תשלח לי בוואטסאפ את הפגישות של היום והלידים שלא נענו", "תתריע לי אם לקוח חייב מעל שבועיים", או "כשנכנס ליד חדש – תבדוק אם הוא לקוח קיים ותגיד לי". משימה כזאת נוצרת בטלפון/בצ'אט (אחרי אישור) או מהלשונית "משימות יזומות" ב-`/admin` (עם דוגמאות מוכנות), ורצה לפי cron, כל X דקות, באירוע מהמערכת (`POST /api/v1/events`) או ידנית.

בהרצה יזומה אין אדם בצד השני, ולכן הסוכן עובד ב**קריאה בלבד**: כלי כתיבה לא מוצעים לו ונחסמים גם אם ינסה, והוא יכול לשלוח **הודעה אחת** לבעל העסק (וואטסאפ דרך ה-CRM, SMS דרך ימות, אימייל, או רק ליומן) – ורק כשיש מה לדווח, עם הצעות לפעולה שמאשרים אחר כך בשיחה. שעות שקט, יומן הרצות עם התמליל המלא, ומדידת עלות לכל הרצה. פירוט: [docs/ROUTINES.md](docs/ROUTINES.md).

## מודל האבטחה

- **סוד ב-URL של המרכזייה** – בלי `WEBHOOK_SECRET` נכון בנתיב, הבקשה נדחית ב-403 לפני כל עיבוד.
- **רשימת מתקשרים מורשים** – מספר שלא ברשימה שומע "המספר הזה לא מורשה להשתמש בעוזר" ומנותק. ההשוואה מנרמלת קידומת 972.
- **קוד גישה אופציונלי** – `BOT_PIN`; עד `maxPinAttempts` ניסיונות (ברירת מחדל 3) ואז ניתוק. נשמר רק כ-hash.
- **אישור בקול לפעולות כתיבה** – כל כלי שמסווג ככתיבה (לפי annotations של השרת או לפי הפועל בשם: `send_`, `update_`, `create_`, `delete_` ...) נחסם בקריאה הראשונה. Claude מקבל הודעת `CONFIRMATION REQUIRED`, מקריא למתקשר מה בדיוק יבוצע, ורק אם הכלי נקרא שוב **בתור הבא** (אחרי שהמתקשר ענה) הוא רץ. כלים שיש להם כבר מנגנון אישור בצד השרת (פרמטר `confirm` / `confirmation_token`) עוברים ישירות. ניתן לכבות ב-`/admin`.
- **רשימת כלים חסומים** – ביטויים רגולריים מול השם המלא של הכלי. ברירת המחדל חוסמת מחיקות (`_delete_` - גם בשמות עם קידומת ספק כמו `sumit_crm_delete_entity`), ביטולים והחזרים בסאמיט (`sumit_documents_cancel`, `sumit_recurring_cancel`, `sumit_payments_refund`, הסרת הרשאות ואמצעי תשלום), `hangup_all_active_calls`, `clear_campaign_entries`, `transfer_units`, `bulk_update_contacts`, `merge_pull_request` ו-`create_repository`. כלי חסום לא רץ אף פעם, גם עם אישור.
- **כלים עם אישור בצד השרת** – כלי שיש לו פרמטר `confirm` / `confirmation_token` עובר בלי חסימה רק בשלב התצוגה המקדימה (בלי `confirm: true` ובלי טוקן); הקריאה שמבצעת בפועל עוברת את אותו אישור בקול כמו כל כתיבה.
- **ממשק הניהול** – ה-API של הניהול מקבל רק JSON ודוחה בקשות cross-site (‏`Sec-Fetch-Site`), כך שדף זדוני לא יכול לנצל את פרטי ה-Basic Auth שהדפדפן זוכר; הדף נשלח עם CSP, ‏`frame-ancestors 'none'` ו-`no-store`. ה-callback של OAuth מתקבל רק להתחברות שהתחילה מכאן, בתוך 15 דקות, עם `state` תואם, ופעם אחת בלבד.
- **שרתים לקריאה בלבד** – `readOnly: true` בקובץ השרתים חוסם כל כתיבה משרת מסוים.
- **הפרדת סודות** – טוקנים ב-`.mcp-auth/` (הרשאות 0600), הסיסמה ל-`/admin` מושווית בזמן קבוע, ה-PIN נשמר כ-SHA-256. ה-callback של OAuth בודק `state`.
- **מגבלות שיחה** – מקסימום תורות (60), תורות שקטים רצופים (2), זמן לתור (`AGENT_TIMEOUT_MS`), וסבבי מודל לתור (12).

## עלויות

**Claude.** תור אחד של המתקשר = בין בקשה אחת לארבע בקשות ל-API (כל סבב כלים הוא בקשה נוספת, עד `maxIterationsPerTurn`). שלושה דברים שומרים על העלות נמוכה:

- **Prompt caching** – פרומפט המערכת (הנחיות העסק, הכללים, רשימת השרתים והכלים הטעונים) מסומן `cache_control`, וכל מה שמשתנה משיחה לשיחה (מספר המתקשר, התאריך) נמצא בהודעת המשתמש הראשונה במקום בפרומפט. במחיר Opus 5 קריאה מהמטמון היא $0.50 למיליון טוקנים לעומת $5 לקלט רגיל. המטמון חי 5 דקות ומתרענן בכל בקשה, כך שבמהלך שיחה הוא תמיד חם.
- **חיפוש כלים** – עם `TOOL_SEARCH=true` רק הכלים שב-`alwaysLoad`, הכלים המקומיים וכלי החיפוש נמצאים בהקשר; מאות הכלים האחרים מסומנים `defer_loading` ונטענים רק כשנמצאים. בלי זה, כל בקשה הייתה נושאת עשרות אלפי טוקנים של הגדרות כלים.
- **תוצאות כלים נחתכות** ל-`MAX_TOOL_RESULT_CHARS`.

אומדן גס ל-Opus 5 (‏$5 קלט / $25 פלט למיליון): תור עם קריאת כלי אחת – בערך 3–6 סנט; תור מורכב עם שלוש-ארבע קריאות – 8–15 סנט; שיחה של עשרה תורות – בסביבות חצי דולר. Sonnet 5 עולה כ-40% מזה, Haiku 4.5 כ-20%. המספרים האמיתיים מופיעים בלשונית **שימוש וטוקנים** (האומדן מחושב מטבלת המחירים ב-`src/usage/pricing.ts` – עדכנו אותה כשהמחירים משתנים).

**מרכזייה.** זיהוי דיבור 0.25 יחידות ל-10 שניות (להיגד), Google TTS חינם, קולות Gemini בתשלום, ובנוסף דקות השיחה הרגילות.

## פתרון תקלות

| תסמין | סיבה ופתרון |
|---|---|
| המרכזייה מקבלת **403** והמתקשר חוזר לתפריט | ה-`WEBHOOK_SECRET` בכתובת שהוגדרה במרכזייה שונה מזה שב-`.env`, או שהמשתנה ריק. בלוג: `PBX request with bad secret`. העתיקו את הכתובת מלשונית **חיבורים**. |
| **400** בבדיקה מהדפדפן | חסר `PBXcallId`. הנקודה מיועדת למרכזייה; לבדיקה ידנית הוסיפו `PBXcallId` ו-`PBXphone` כמו בדוגמת ה-curl למעלה. |
| המתקשר שומע **"המספר הזה לא מורשה"** | המספר לא ב-`ALLOWED_CALLER_PHONES` / ברשימה ב-`/admin`. זכרו שאחרי שמירה מ-`/admin` הרשימה ב-`data/settings.json` גוברת על `.env`. בלוג: `caller not in allow-list` עם המספר כפי שהמרכזייה שלחה אותו. |
| **"נדרשת התחברות"** בלשונית חיבורים, או שהבוט אומר שהשירות דורש התחברות | טוקן ה-OAuth פג או בוטל. לחצו **התחבר**. אם זה קורה אחרי כל פריסה – `MCP_AUTH_DIR` לא נשמר (ב-Docker: ודאו ש-`.mcp-auth` ממופה כ-volume). |
| ההתחברות חוזרת לכתובת שגויה / **OAuth state mismatch** | `PUBLIC_BASE_URL` חייב להיות בדיוק הכתובת שממנה נכנסים ל-`/admin` (עם `https`, בלי `/` בסוף). התחילו את ההתחברות מחדש. |
| שגיאות **431 / 414 / 400** על בקשות ארוכות, בעיקר בשיחות ארוכות | המרכזייה צוברת את כל ההיגדים ב-query string. השרת עצמו מקבל כותרות עד 128KB (‏`maxHeaderSize` ב-`src/server.ts`), אבל ה-reverse proxy עלול לחסום קודם: ב-nginx הגדירו `large_client_header_buffers 4 128k;`, ב-Caddy ברירת המחדל מספיקה. אם משתמשים ב-CDN, בדקו את מגבלת אורך ה-URL שלו. הקטנת `maxTurns` ב-`/admin` מגבילה את אורך השיחה. |
| **עברית משובשת** בהקראה | התשובה חייבת לצאת עם `Content-Type: application/json; charset=utf-8` – השרת שולח כך; ודאו שה-proxy לא משכתב את הכותרת (`curl -i`). קבצי `.env` ו-`config/instructions.md` חייבים להישמר ב-UTF-8 (קובץ שנשמר ב-Windows-1255 ישבש את ברכת הפתיחה). |
| המתקשר שומע "רק רגע" שוב ושוב, או שהשיחה נופלת אחרי כ-30 שניות | `PBX_LONG_POLL_MS` חייב להיות מתחת ל-30 שניות (ברירת מחדל 20). אם ה-proxy מנתק בקשות קצרות מזה (למשל `proxy_read_timeout 10s`), הגדילו אותו ל-60 שניות לפחות. תורות ארוכים במיוחד – הקטינו `BOT_EFFORT` או הוסיפו כלים ל-`alwaysLoad` כדי לחסוך סבבי חיפוש. |
| `/admin` מחזיר **503 "ממשק הניהול כבוי"** | `ADMIN_USER` או `ADMIN_PASSWORD` ריקים. |
| הבוט אומר "יש בעיה בהגדרות החיבור למנוע הבינה" | `ANTHROPIC_API_KEY` שגוי או חסר. |
| "יש עומס רגעי על המערכת" | Rate limit מול ה-API. נסו שוב; שקלו מודל זול יותר או רמת מאמץ נמוכה יותר. |
| שרת MCP במצב **error** | הכתובת שגויה, השרת לא זמין או `transport` לא מתאים. הודעת השגיאה מופיעה בטבלה; נסו `"transport": "sse"`. השרת לא חוסם את עליית הבוט. |
| שינוי ב-`config/mcp-servers.json` לא נקלט | הקובץ נטען רק בעלייה – הפעילו מחדש. |

## שאלות נפוצות

**האם צריך לשנות קוד כדי להחליף מודל?** לא. בוחרים ב-`/admin` → הגדרות, והשינוי חל על השיחה הבאה (ואפילו על התור הבא בשיחה פעילה).

**הבוט יכול לשלוח הודעה בלי שאישרתי?** לא כל עוד "לבקש אישור מהמתקשר לפני פעולות כתיבה" מסומן. הכלי נחסם טכנית בקריאה הראשונה; המודל חייב להקריא את הפרטים ולקבל "כן" בתור הבא. כלים שברשימה החסומה לא ירוצו בכלל.

**איך מלמדים את הבוט כלל קבוע?** אומרים בשיחה "מעכשיו, כשאתה מדווח על לידים תמיד תגיד גם טלפון". הבוט מנסח כלל, מקריא אותו, ואחרי אישור שומר אותו (`data/rules.json`). הכלל נכנס לפרומפט מהשיחה הבאה. אפשר לערוך ולמחוק כללים ב-`/admin` → כללים והוראות.

**מה קורה אם השרת מופעל מחדש באמצע שיחה?** הבקשה הבאה מהמרכזייה מכילה את כל ההיגדים (`utt_N`), והשרת מזהה את האחרון וממשיך בלי לברך שוב – אבל זיכרון השיחה (ההיסטוריה מול Claude) אבד, אז כדאי לחזור על הבקשה.

**כמה שיחות במקביל?** אין מגבלה בקוד – לכל שיחה סשן משלה. בפועל המגבלה היא ה-rate limit של Anthropic ומספר הערוצים במרכזייה.

**אפשר לחבר מרכזייה אחרת?** המתאם ב-`src/pbx/technoline/` ספציפי לפרוטוקול של טכנוליין. מרכזייה אחרת דורשת מתאם חדש באותה תיקייה; הסוכן, ה-MCP והניהול לא תלויים במרכזייה.

**איפה התמלילים?** ב-`data/usage/YYYY-MM.jsonl` (אירועי `turn`) ובלשונית **שימוש וטוקנים**. שימו לב שזה מידע עסקי רגיש – גבו אותו והגבילו גישה.

**איך מוסיפים שרת MCP?** מוסיפים אובייקט ל-`config/mcp-servers.json`, מפעילים מחדש, ומתחברים מ-`/admin`. שרת חדש נכנס לפרומפט אוטומטית.

**למה יש הבדל בין המספר שהמרכזייה שולחת לרשימה שלי?** המרכזייה שולחת לפעמים `972...` ולפעמים `0...`; ההשוואה מנרמלת את שניהם. אם עדיין לא מזוהה, העתיקו את המספר מהלוג (`caller not in allow-list`).

**האם אפשר להריץ שני מופעים לגיבוי?** לא – השיחות הפעילות בזיכרון של תהליך אחד. הריצו מופע אחד עם הפעלה מחדש אוטומטית (PM2 / Docker `restart: unless-stopped`).
