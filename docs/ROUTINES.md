# משימות יזומות (Routines)

העוזר לא רק עונה כשמתקשרים אליו – הוא יכול לבדוק דברים בעצמו, לפי לוח זמנים או כשמגיע אירוע מהמערכת, ולשלוח לבעל העסק הודעה רק כשיש משהו שדורש תשומת לב, עם הצעות לפעולה. זה אותו מנוע (אותו מודל, אותם כלי MCP, אותם כללים קבועים והוראות עסקיות), במצב עבודה מיוחד: **קריאה בלבד + הודעה אחת**.

## מה קורה בהרצה

1. המתזמן (בודק כל 30 שניות) מוצא משימה שהגיע זמנה, או שמגיע אירוע ל-`POST /api/v1/events`, או שלוחצים "הרץ עכשיו" ב-`/admin`.
2. נפתחת שיחה חדשה של הסוכן בערוץ `proactive`. הפרומפט אומר לו שאין אדם בצד השני, שכלי כתיבה חסומים, ושמותר לשלוח לכל היותר הודעה אחת עם `notify_owner` – ורק אם יש מה לדווח.
3. רשימת הכלים שהמודל רואה כוללת רק כלי **קריאה** (לפי הסיווג של שער האישורים) + `list_rules`, `list_routines` ו-`notify_owner`. גם אם המודל ינסה לקרוא לכלי כתיבה, השרת מסרב ומחזיר לו הודעה להציע את הפעולה לבעל העסק במקום לבצע אותה.
4. `notify_owner` שולח את ההודעה בערוץ של המשימה (ראו למטה). קריאה שנייה באותה הרצה נדחית.
5. הדוח הסופי של המודל (מה בדק, מה מצא) נשמר ביומן ההרצות ולא נשלח לאף אחד. כל הרצה נרשמת גם ביומן השימוש (טוקנים, כלים, עלות) עם מזהה `routine-<id>-<זמן>`, אז אפשר לפתוח את התמליל המלא מהלשונית "שימוש וטוקנים".

ההרצות מבוצעות **בזו אחר זו** (תור), כך שגם עשר משימות באותה דקה לא מציפות את שרתי ה-MCP או את המודל.

## סוגי לוח זמנים

| סוג | מה זה | דוגמה |
|---|---|---|
| `cron` | ביטוי cron של 5 שדות (דקה שעה יום חודש יום-בשבוע) לפי שעון ישראל, 0 = ראשון | `0 8 * * 0-4` – ימים א'–ה' ב-08:00 |
| `interval` | כל N דקות (5–10080) מסיום ההרצה הקודמת | `everyMinutes: 30` |
| `event` | רץ כשמערכת חיצונית שולחת אירוע מהסוגים ברשימה (`*` = כל אירוע) | `eventTypes: ["new_lead"]` |
| `manual` | רק בלחיצה על "הרץ עכשיו" או דרך ה-API | – |

תבניות מוכנות ב-`/admin`: כל יום ב-08:00, א'–ה' ב-09:00 או ב-20:00, כל שעה בשעות העבודה (`0 9-18 * * 0-4`), כל יום שישי ב-12:00, ב-1 לחודש.

**שעות שקט** – משימות מתוזמנות (cron/interval) לא רצות בחלון השקט (ברירת מחדל 22:00–07:00, ניתן לשינוי בהגדרות או למשימה ספציפית). אירועים והרצות ידניות רצים תמיד. אחרי הפעלה מחדש של השרת, משימת cron שזמנה חלף לא "מתפצה" – היא תרוץ במועד הבא.

## ערוצי ההודעה

| ערוץ | איך נשלח | מה צריך להגדיר |
|---|---|---|
| `log` | רק נרשם ביומן (ברירת מחדל – בטוח לבדיקות) | כלום |
| `whatsapp` | `crm__send_whatsapp` דרך ה-CRM | הטלפון של בעל העסק בהגדרות, CRM מחובר |
| `sms` | `yemot__send_sms` דרך ימות המשיח | הטלפון של בעל העסק, שרת ימות מחובר |
| `email` | `crm__send_email` דרך ה-CRM | האימייל של בעל העסק, CRM מחובר |

המיפוי ערוץ → כלי נשמר ב-`settings.notifyTemplates` וניתן לשינוי דרך `PUT /admin/api/settings` (למשל כדי לשלוח וואטסאפ דרך שרת אחר). משתנים בתבנית: `{{text}}`, `{{subject}}`, `{{ownerPhone}}` (0501234567), `{{ownerPhoneIntl}}` (972501234567), `{{ownerEmail}}`.

כפתור **"שלח הודעת בדיקה"** בלשונית ההגדרות שולח הודעת ניסיון בערוץ השמור – כדאי ללחוץ עליו פעם אחת לפני שסומכים על התראות אמיתיות.

## יצירת משימה

**מ-`/admin` → "משימות יזומות"**: שם, ערוץ, לוח זמנים, ההנחיה. יש רשימת דוגמאות מוכנות (תדריך בוקר, לידים ללא מענה, חובות פתוחים, סיכום שבועי, ליד חדש, תור ימות) שממלאות את הטופס.

**בטלפון או בצ'אט**: "כל בוקר בשמונה תשלח לי בוואטסאפ סיכום של הפגישות והלידים". העוזר מנסח משימה (`add_routine`), מקריא את השם, לוח הזמנים והערוץ, ויוצר אותה רק אחרי "כן" – בדיוק כמו כל פעולת כתיבה. אפשר גם "אילו משימות יש לך?" (`list_routines`), "תכבה את תדריך הבוקר" (`toggle_routine`) ו"תמחק את המשימה..." (`remove_routine`).

**דרך ה-API** (‏Basic Auth של הניהול):

```
GET    /admin/api/routines                → { enabled, routines: [...+nextRunAt, running], notifications }
POST   /admin/api/routines                { name, schedule, prompt, channel?, quietHours?, enabled? }
PUT    /admin/api/routines/:id            (כל תת-קבוצה של השדות)
DELETE /admin/api/routines/:id
POST   /admin/api/routines/:id/run        מריץ עכשיו ומחכה לתוצאה
GET    /admin/api/routines/:id/runs       יומן ההרצות (50 אחרונות)
POST   /admin/api/notify/test             { channel?, text? }
```

## כתיבת הנחיה טובה

ההנחיה היא משימה שלמה שהמודל מקבל בלי הקשר נוסף. שלושה חלקים עובדים הכי טוב:

1. **מה לבדוק** – "בדוק ב-CRM את הלידים שנוצרו ב-24 השעות האחרונות ואת הפניות שלא נענו."
2. **מתי שווה להודיע** – "שלח הודעה רק אם יש ליד שממתין מעל 3 שעות או יותר מחמישה לידים חדשים. אחרת אל תשלח."
3. **מה להציע** – "לכל ליד: שם, טלפון, מה ביקש; והצע למי לחזור קודם ואיזו הודעה לשלוח."

אם רוצים דוח יומי גם כשאין חדש, יש לכתוב זאת במפורש ("שלח תמיד, גם אם יום רגוע").

## אירועים מהמערכת (webhook)

מערכת חיצונית (ה-CRM, סאמיט, אוטומציה) שולחת:

```
POST /api/v1/events
Authorization: Bearer <CHAT_API_KEY>
Content-Type: application/json

{ "type": "new_lead", "payload": { "name": "דני", "phone": "0501234567", "source": "אתר" } }
```

התשובה `202 { ok, type, routines: [ids] }` חוזרת מיד; ההרצות עצמן רצות ברקע. `type` – אותיות, ספרות, `_ . : -` עד 64 תווים; `payload` – כל JSON עד 20,000 תווים, מצורף להנחיה כ"נתוני האירוע". ב-CRM זה מתחבר בקלות לכללי האוטומציה או ל-webhook endpoints הקיימים.

## הגדרות רלוונטיות (`/admin` → הגדרות → "התראות לבעל העסק ומשימות יזומות")

| הגדרה | ברירת מחדל | הסבר |
|---|---|---|
| `routinesEnabled` | `true` | מתג ראשי למתזמן (הרצה ידנית ממשיכה לעבוד) |
| `ownerPhone` / `ownerEmail` | מ-`OWNER_PHONE` / `OWNER_EMAIL` | יעד ההודעות |
| `notifyChannel` | `log` | ערוץ ברירת מחדל למשימות שנוצרות בטלפון/צ'אט |
| `quietHours` | `22:00`–`07:00` | חלון שבו משימות מתוזמנות לא רצות |
| `notifyTemplates` | whatsapp/sms/email | מיפוי ערוץ → כלי MCP |

הנתונים נשמרים ב-`data/routines.json` (עד 100 משימות). ב-CapRover הספרייה `/app/data` כבר מוגדרת כקבועה, אז המשימות שורדות פריסה מחדש.

## מה זה עולה

כל הרצה היא שיחה רגילה של הסוכן: פרומפט מערכת מהמטמון + כמה קריאות כלים + תשובה קצרה. תדריך בוקר יומי עם 3–5 כלים עולה סנטים בודדים; משימה כל 15 דקות בשעות העבודה כבר מצטברת – בודקים בלשונית "שימוש וטוקנים" (ההרצות מופיעות כשיחות עם מזהה `routine-...`). כדאי להתחיל בערוץ `log`, להסתכל ביומן ההרצות מה המודל היה שולח, ורק אז לעבור לוואטסאפ.
